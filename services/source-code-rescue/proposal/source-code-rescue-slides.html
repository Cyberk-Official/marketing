What every

  • 01What is wrong and exactly where it is in the code.
  • 02The risk in words a non-technical reader understands.
  • 03Severity Critical, High, Medium or Low.
  • 04How to fix it step by step, with code examples where they help.
  • 05Acceptance criteria how we will check that it is fixed.
  • 06Time estimate so you can plan around real numbers.
SEC-03CRITICALEst. 0.5 day

Any logged-in user can read other users' orders

Where

api/orders · order detail endpoint

Risk

A customer who changes the number in the page address can see another customer's name, address and order history.

How to fix
  1. Check the order belongs to the logged-in user before returning it.
  2. Apply the same check to the order list and invoice endpoints.
  3. Add a test that fails if one user can fetch another user's order.
Done when

Requesting another user's order returns “not found”, and the new test passes in CI.
